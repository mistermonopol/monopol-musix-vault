# Musix Vault Brain

This Obsidian vault is the human-editable knowledge layer for Monopol Musix Vault. It captures musical context that file tags alone cannot express: relationships, moods, influences, scenes, personal notes, and curated classifications.

The complete vault, including its `.obsidian` configuration, is versioned in the same Git repository as the application.

## Data model

Each track note uses YAML properties for structured values and Obsidian wikilinks for relationships. The canonical note types are:

- Track
- Artist
- Album
- Genre
- Playlist

Track notes should use a stable `track_id` generated by the backend. A filename or filesystem path must not be used as an identity because either can change. Until backend synchronization is available, `track_id` may remain empty.

Use links such as `[[Artist Name]]`, `[[Album Name]]`, and `[[Genre Name]]` to build the graph. Use Obsidian tags for broad workflow and classification labels, not as replacements for linked entities.

## Track notes

Create track notes from `Templates/Track.md`. Keep metadata factual and structured in properties; use the note body for editorial context, relationships, memories, and listening observations.

The future synchronization service will treat database scanner metadata as authoritative for technical file properties and Obsidian as authoritative for editorial properties. Conflicts will be reported rather than silently overwritten.

## Development handoff

Current architecture, deployment state, security decisions, and the prioritized backlog are maintained in `[[Development/Agent Handoff]]` so a new agent session can continue without relying on chat history.

## Privacy

Do not store passwords, API tokens, private keys, or absolute local music paths in this vault. Everything committed here may be uploaded to GitHub.
